# 本地复核

验证环境为 Python 3.13，依赖版本固定在 `code/requirements-analysis.txt`。首次配置：

```bash
python3.13 -m venv work/venv
work/venv/bin/python -m pip install -r code/requirements-analysis.txt
```

论文构建需要 TeX Live 或 MacTeX 的 `latexmk`、pdfLaTeX，以及 Poppler 的 `pdfinfo`、`pdffonts`、`pdftotext`。GPU 推理环境以 `data/protocols/inference_environment.json` 为准，不用分析环境替代。

CPU 和主语言原始包从[数据下载入口](../data/README.md#原始数据下载)获取，分别保存为 `data/archives/cpu.tar.gz`、`data/archives/language.tar.gz`。这两个本地文件由 Git 忽略。程序会核对清单中的准确字节数和 SHA-256；未下载时会给出链接与保存位置。

依赖及两个外部包齐备后，一条命令完成全部本地复核：

```bash
KBS_PYTHON=work/venv/bin/python bash code/scripts/kbs_project.sh all
```

| 命令 | 工作 |
| --- | --- |
| `verify` | 核对材料清单、已下载包的哈希和源码绑定，单列尚未下载的外部包；不解包，仅需 Python 标准库 |
| `check` | 自动解包，核对 S1、CPU、语言、H、成本记录和论文表格，运行正确性测试 |
| `test` | 只运行测试，自动准备必要语言输入 |
| `prepare cpu` | 校验并解包已下载的 CPU 包；也可选择 `language`、`experiment_h` 或 `s1` |
| `analyze-cpu` | 从保存计数输出全部规模和构造分层统计 |
| `replay-costs` | 复现 E5/E7 CPU 核验与停止逻辑，逐字段比较原记录 |
| `figures` | 另存两张图及绘图点，不覆盖论文原图 |
| `build` | 在独立目录编译论文，检查引用、越界和字体，通过后更新 `latex/main.pdf` |

以上命令均通过 `bash code/scripts/kbs_project.sh <命令>` 调用，不下载模型或派发推理请求。首次完整复核会解包约 705 MiB 记录；每次运行使用新的 `work/` 结果目录。原始压缩包不修改，缓存中的记录也不作为新的结果写入位置。

[code/project/manifest.json](../code/project/manifest.json) 固定本次交接材料。改动后出现清单差异时，先检查改动范围，再运行针对性测试；不要为了通过检查直接改哈希。源码或协议的实质变更需要新的批次和清单。

论文采用 Elsevier `elsarticle` 的 `final,5p,times,twocolumn` 设置。`elsarticle.cls`（3.4，2024-04-04）由[Elsevier 官方指南](https://www.elsevier.com/researcher/author/policies-and-guidelines/latex-instructions)所提供模板包中的 `elsarticle.ins` 与 `elsarticle.dtx` 生成；`elsarticle-num-names.bst` 直接取自同一包。两文件均与该官方包逐字节核对一致，未作修改。其他宏包使用 TeX 发行版中的标准文件，论文的定理和符号定义放在 `main.tex` 导言区。

官方包 SHA-256 为 `0b093093e84db49f99bcc9a7c3f69ed1fb61b0147c6d296427aff7963e7f50f6`。这是本项目采用版本的来源记录，不代表该包是所有渠道的最新版本。期刊作者指南本次访问仍为 HTTP 403；投稿前须补核 KBS 的栏数要求、作者元数据与声明。编译通过不等于已完成投稿要求。

现有验证区分保存结果重放、CPU 核验、模型推理和示意图计算。Tokenizer 渲染后的提示词哈希本次没有重建；图的 PDF 字节可能随渲染环境不同，但绘图点必须一致。主实验和 H 的未完成状态见 [工作计划](工作计划.md)。

## 已有核查记录

2026-11-02 的材料核查通过 54 项测试，核对了 112,393 个原始实验文件的哈希和 62 个冻结源码依赖。S1、CPU 与语言校准表能够由保存记录重建；E5/E7 各 3,464 条成本记录可逐字段重放，14,336 个 CPU 绘图点一致。

这些检查验证的是材料完整性、实现与保存结果的一致性。主语言测试集仍不完整，H 尚无本地模型响应，完整流程成本比较尚未完成。具体缺口见[工作计划](工作计划.md)，研究问题与完成标准见[研究方案](研究方案.md)。每次重新复核都会在 `work/` 中保存独立结果和日志。
