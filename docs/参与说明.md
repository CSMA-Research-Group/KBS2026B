# 参与说明

先理解论文的决策问题，再复现已有结果，最后认领一项具体工作。当前重点是把既定实验做完整、把实现与论文证据对齐。

## 接手顺序

1. 先读[研究方案](研究方案.md)，再阅读论文摘要、第 3—4 节和实验设计。能够说明三个研究问题、四种决策，以及语义允许、物理可行、已获得证据三者的区别。
2. 按 [复核说明](复核说明.md) 配置环境，运行 `check`。记录环境、命令、结果目录和失败信息，核对论文中的 S1、CPU 和校准表。
3. 从下表选择一个方向，先提交一份简短理解说明和一次可重复运行的结果，再开始修改。

| 方向 | 首个任务 | 交付与完成标准 |
| --- | --- | --- |
| 代码与正确性 | 阅读 `language_interface.py`、`runtime_checks.py` 和对应测试；追踪一个实例从输入到决策的全过程 | 给出真实实例 ID、函数调用顺序和中间集合；用一个边界例子检验解释；能够复现已有测试 |
| 数据与主实验 | 核对每个模型×领域×表示单元的请求和响应覆盖率，区分缺失、失败与有效输出 | 导出覆盖率表和缺失请求清单，与保存数据逐项对应；不得把未完成单元算成完整结果 |
| 机制与成本 | 先复现 E5/E7，再阅读 H 的场景变换 | 成本记录逐字段一致；说明比较单位、停止规则和局限；H 只做已确定的 π=0.25 条件 |
| 论文与图表 | 按数据说明追踪一张表和一幅图，核对正文中的解释 | 提供数据位置、计算入口和对应数值；修改后编译并检查 PDF；不扩大现有证据支持的结论 |

## 协作方式

每次工作只解决一个明确问题。提交时附上修改文件、运行命令、结果位置、主要发现和未解决事项。报错保留完整日志，不只提供截图或口头结论。

原始证据包不修改。现有科学协议、校准划分、种子和成功请求保持固定；需要更改方法时先说明原因和影响，使用新的实验批次。分析输出另存到 `work/`，不覆盖已有批次。

首次接手以本地复核为主。服务器推理需核对真实进程、模型文件和任务归属，已有成功请求不重复执行。暂不增加模型、领域、提示词扫描、样本量或人工标注。
